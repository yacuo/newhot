# 架构与运行

## 1. 运行形态

- Astro 7 静态站，`output: "static"`，产物在 `dist/`。
- 内容全部是 Markdown + frontmatter，构建期读取，无数据库。
- 站点内容全部在构建期生成，产物可部署到任意静态托管平台。
- 站点 URL 默认读取内容项目 `config/global/site.json` 的 `url`，以 `SITE_URL` 覆盖。

## 2. 技术栈

| 层 | 技术 |
| --- | --- |
| 框架 | Astro 7（静态输出，无 adapter） |
| 样式 | Tailwind CSS v4（`@tailwindcss/vite`） |
| 内容 | Markdown + gray-matter frontmatter |
| 校验 | Zod（构建期，失败即中止） |
| Markdown 渲染 | unified 管线：remark-gfm → rehype-slug → rehype-autolink-headings → rehype-highlight |
| 交互 | 原生 TypeScript（`src/features/`、`src/app/scripts/`），无 UI 框架运行时 |
| 部署 | `astro build` 产出 `dist/`，可部署到任意静态托管 |

## 3. 目录职责

```
src/app/                应用骨架：layouts、shell、scripts、styles、analytics、routing
src/views/              页面级组合；src/pages 只保留薄路由与 getStaticPaths
src/features/           交互功能：search、article-list、article-toc、history-timeline、tabs、mermaid
src/entities/           领域层：article、channel、vendor、tutorial、release、page-content、agent
src/shared/             跨层能力：config、content、lib、seo、ui
src/pages/              Astro 文件路由
config/                 站点配置：global（site/content-types/sources/search）、channels、各页面文案
data/channels/          频道文章：<channel>/<subcategory>/posts/*.md
data/tutorials/         教程文章
data/vendors/           公司主数据、主题归属、发展史与 SEO
data/update-log/posts/  更新日志文章
scripts/                构建期校验与数据生成、预算检查
public/                 静态资源与构建期生成物（整目录复制到 dist）
ops/                    本地启停脚本
docs/                   本目录
```

## 3.1 分层与依赖规则

采用 Feature-Sliced Design 的分层，依赖只能自上而下：

```
pages → views → features → entities → shared
```

- `pages/`：只保留 Astro 路由、`getStaticPaths` 与薄包装，不写页面结构。
- `views/`：页面级组合，按路由组织（home、entity、subcategory、theme、agent 等）。
- `features/`：可交互能力（搜索、列表加载、目录、时间线、标签页、Mermaid），含 `model/` 与 `ui/`。
- `entities/`：领域模型与领域 UI（article、channel、vendor、tutorial、release、page-content、agent）。
- `shared/`：配置、内容读取、SEO、通用 UI 与工具，不得反向依赖上层。
- 禁止跨层反向 import；需要复用的能力先下沉到 `shared/` 或对应 `entity`。

## 4. 路由

路由全景、`getStaticPaths`、数据读取与组件分层见 [页面与路由.md](./页面与路由.md)。

文章 canonical 固定为 `/{subcategory}/{slug}/`，不使用教程路径覆盖。

## 5. 构建数据流

```
Markdown
  → content:feed:  public/data/feed/home.json + meta.json
  → content:lists: public/data/lists/<scope>/<n>.json   # 列表分片，滚动与搜索按需加载
  → astro build → dist/
```

## 6. 命令

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 生成 feed/lists + Astro 开发服务（4321） |
| `npm run build` | 生成数据 + 静态构建 `dist/` |
| `npm run preview` | 本地预览 `dist/`（4321） |
| `npm run check` | 配置校验 + `astro check` 类型检查 |
| `npm run check:config` | 只校验 `config/` 下的配置（Zod schema） |
| `npm run content:feed` | 生成 `public/data/feed/home.json` 与 `meta.json` |
| `npm run content:lists` | 生成 `public/data/lists/<scope>/<n>.json`，每片 50 条 |
| `npm run check:budget` | 检查 HTML/CSS/JS/请求数预算 |

## 7. 环境变量

本地变量放在项目根目录的 `.env`（不提交，拷贝 `.env.example` 后填写）；本机覆盖项写 `.env.local`（不提交）。

| 变量 | 作用 |
| --- | --- |
| `CONTENT_DIR` | 内容项目根目录（含 `config/` 与 `data/`），默认站点仓库自身；仓库内的 `config/`、`data/` 都只是示例，真实配置不要提交到公开仓库 |
| `SITE_URL` | 站点绝对 URL，影响 canonical 与 sitemap；优先于 `config/global/site.json` 的 `url` |
| `API_BASE_URL` | Agent API / MCP / Skill 文档中的服务地址；优先于 `config/global/site.json` 的 `apiBaseUrl` |
| `SITE_NOINDEX` | `1` 时全站 noindex + `robots.txt` Disallow，用于上线前封禁 |
| `PUBLIC_BUILD_ID` | 构建版本号，写入 `<meta name="newhot-build">`，数据分片地址据此加 `?v=` |
| `PUBLIC_GA_ID` | Google Analytics 4 衡量 ID；留空不输出统计代码 |
| `PUBLIC_BAIDU_TONGJI_ID` | 百度统计站点 ID；留空不输出统计代码 |
| `PUBLIC_BING_VERIFICATION` | 必应站长工具验证码；留空不输出验证 meta |
| `ASTRO_TELEMETRY_DISABLED` | 脚本内固定为 1，避免遥测写系统目录 |

## 8. 配置校验

配置契约用 Zod 定义：

- 通用配置：`src/shared/config/schemas.ts`（site / content-types / sources / search）
- 频道与分类：`src/entities/channel/model/model.ts`
- 页面配置：`src/entities/page-content/model/*.ts`
- 教程配置：`src/entities/tutorial/model/catalog.ts`

`npm run check:config` 会逐项校验 `config/`，字段类型错误、未知字段、缺失字段都会直接失败并指出位置。`dev`、`build`、`check` 都会先跑这一步。

## 9. 上线守卫

上线前必须满足：

1. `npm run build` 成功，`npm run check` 0 error。
2. `npm run check:budget` 通过。
3. 文章页输出自指 canonical、`author`、`NewsArticle`（pricing 为 `Article`）/ `BreadcrumbList` / `FAQPage` / `DefinedTermSet`。
4. sitemap 包含全部频道、分类和文章。
5. 预览构建使用 `SITE_NOINDEX=1`；确认后再去掉该变量并重新构建。

真实部署与回滚由站点维护者负责，不在仓库内提供部署配置。

## 10. 工程约定

- TypeScript strict；禁止 `any`。
- 交互只用原生 TS，脚本只读 `data-*` 属性，不依赖框架状态。
- 路径别名 `@/*` 指向 `src/*`。
- 站点 URL 只能来自 `siteConfig` / `getSiteUrl()` / `SITE_URL`，禁止硬编码域名。
- Agent 文档里的 API、MCP、Skill 地址只能来自 `getApiUrl()` / `getApiBaseUrl()`，品牌名来自 `siteConfig.name`。
- 页面数据只能通过 `src/entities/article/model/` 的读取函数，组件里不直接读 `data/` 或 `public/`。
- 新增可访问路由必须同时补 `getStaticPaths`，并保持 URL 带尾斜杠；否则构建后是 404。
- 样式只消费 `src/app/styles/global.css` 的 token，不新增任意色值、字号和间距。
- `public/data/`、sitemap 由 `scripts/` 生成，不手改。
- 新增频道/分类必须同步：`config/channels/<channel>.json` 的频道字段与 `subcategories`，并在 `config/global/content-types.json` 的 `defaults` 中补默认 `type`。

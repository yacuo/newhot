# 页面与路由

## 1. 路由

| 路径 | 文件 | 渲染 |
| --- | --- | --- |
| `/` | `src/pages/index.astro` | 首页：置顶与层级筛选，首屏 20 条 |
| `/{channel}/` | `src/pages/[slug]/index.astro` | 频道列表 + 频道说明 |
| `/{companyId}/` | 同上 | 公司详情：跨频道动态 |
| `/{channel}/{subcategory}/` | `src/pages/[slug]/[subcategory]/index.astro` | 分类时间线 |
| `/{subcategory}/{slug}/` | 同上 | 文章详情 |
| `/{tutorialId}/{slug}/` | 同上 | 教程文章 |
| `/themes/` | `src/pages/themes/index.astro` | 主题索引 |
| `/themes/{theme}/` | `src/pages/themes/[theme]/index.astro` | 单主题公司列表 |
| `/topics/` `/companies/` `/tutorials/` | 同名目录 | 全站索引 |
| `/tutorials/{tutorialId}/` | `src/pages/tutorials/[tutorialId]/index.astro` | 教程目录 |
| `/about/`、`/update-log/`、`/open-source/`、`/privacy/`、`/terms/`、`/contribute/`、`/contact/`、`/cookies/`、`/do-not-sell/` | 同名目录 | 静态页 |
| `/update-log/{slug}/` | `src/pages/update-log/[slug]/index.astro` | 日志详情 |
| `/sitemap.xml`、`/sitemaps/*.xml`、`/robots.txt` | `src/pages/**/*.ts` | Endpoint |
| `/404` | `src/pages/404.astro` | 构建为 `dist/404.html` |

`src/pages/[slug]/[subcategory]/index.astro` 的判定顺序：

1. `kind === "category"` → 分类页。
2. `kind === "tutorial"` → 教程文章。
3. `kind === "post"` → 文章详情。

一级路由 `src/pages/[slug]/index.astro` 先判公司 id，再判频道 id；公司详情只占一级路径。

## 2. 静态生成约束

- `getStaticPaths` 必须覆盖全部路径，缺一页即缺失。
- 输出为 `dist/<path>/index.html`（`build.format: "directory"`），URL 统一带尾斜杠。
- 新增内容形态或路由时，先补 `getStaticPaths`，构建后确认 `dist/<path>/index.html` 有产出。

## 3. 数据来源

| 页面 | 读取方式 | 数据 |
| --- | --- | --- |
| 首页 | `readHomeFeed()` + 分片 | `home.json` 各层级首屏 20 条；切换层级读 `_latest/<tier>/<n>.json` |
| 频道、分类 | `readFeedMeta()` + `readListShard(scope, 1)` | `meta.json` 计数，首屏 20 条 |
| 公司详情 | `readFeedMeta()` + `readListShard` + 分片 | `_companies/<id>/<n>.json` |
| 主题页 | `themes.json` + `meta.json` | 只聚合公司卡片，不读文章分片 |
| 文章详情 | `getAllPosts()` | 扫描 `data/**/*.md`，`postMetaSchema` 校验 |
| 教程 | `getResolvedTutorialCatalogs(posts)` | `data/tutorials/<id>/catalog.json` + `articles/*.md` |
| 静态页 | `loadPageData(pageId, sections)` | `data/<pageId>/*.json` |

规则：

- 列表页只读预生成 feed，不在构建时重复扫描 Markdown。
- 文章页才用 `getAllPosts()`，结果按进程缓存。
- 搜索复用频道分片：打开不请求，输入 ≥2 字才拉第 1 片，命中不足自动补页，最多 6 条、4 页；不搜正文。
- 列表首屏 20 条，滚动或点击「加载更多」每次追加 2 条，分片 50 条。
- 组件不直接 `fs`，统一走 `src/entities/article/model/`。

## 4. 组件分层

| 目录 | 职责 |
| --- | --- |
| `src/pages/` | 路由与 `getStaticPaths`，只做薄包装 |
| `src/views/` | 页面级组合：home、entity、subcategory、theme、tutorial、agent 等 |
| `src/app/` | `layouts`、`shell`（顶栏/侧栏/页脚/抽屉/主题）、全局脚本、样式、统计 |
| `src/features/` | 搜索、列表加载、目录、时间线、标签页、Mermaid 等交互功能 |
| `src/entities/article/` | 文章 frontmatter、Markdown、数据读取与文章级 UI |
| `src/entities/channel/` | 频道/分类模型与频道导航、时间线、列表、写作标准 |
| `src/entities/vendor/` | 公司、主题、发展史模型与公司页 UI |
| `src/entities/tutorial/` | 教程目录、文章模型与教程 UI |
| `src/entities/page-content/` | 静态页 JSON 的 schema 与读取 |
| `src/shared/` | config、content、lib、seo、ui 等跨层能力 |

默认纯静态渲染。只有 `src/features/` 与 `src/app/scripts/` 中的脚本会进入浏览器，且只在需要时加载；搜索脚本在首次点击时动态 `import`。

## 5. SEO

- `src/app/layouts/Root.astro` 输出 `Organization`、`WebSite` JSON-LD，并注入构建版本号与启动脚本。
- 每页通过 `SeoHead.astro` 输出 title、description、canonical、Open Graph、Twitter Card。
- 频道页 SEO 来自 `channel.json` 的 `seo`；分类页来自 `subcategory.json`；公司页来自 `company-seo.json`。
- 不输出 meta keywords。
- 文章 canonical 固定为 `/{subcategory}/{slug}/`。
- 文章 JSON-LD：`NewsArticle`（pricing 为 `Article`）、`BreadcrumbList`、`FAQPage`、`DefinedTermSet`。
- sitemap 拆成 `core`、`categories`、`tutorials`、`articles` 四张子图，由 `src/shared/seo/sitemap.ts` 生成。

## 6. 构建期产物

| 产物 | 生成脚本 | 消费方 |
| --- | --- | --- |
| `public/data/feed/home.json` | `scripts/generate-article-feeds.ts` | 首页 |
| `public/data/feed/meta.json` | `scripts/generate-article-feeds.ts` | 频道 / 分类 / 公司 / 关于页 |
| `public/data/lists/<scope>/<n>.json` | `scripts/generate-article-lists.ts` | 加载更多、搜索 |

`public/` 整目录复制到 `dist/`，因此 `logos`、`og`、`sitemap.xsl` 无需额外处理；响应头与跳转规则由托管平台的部署配置决定，不放在仓库里。

## 7. 样式

- Tailwind CSS v4，通过 `@tailwindcss/vite` 处理；`postcss.config` 已移除。
- 设计 token 在 `src/app/styles/global.css`，主题色在 `src/app/styles/accents/`。
- 只用 token 表达颜色、字号、间距、圆角；不在组件里新增任意色值。
- 页面容器、面板优先用 `src/shared/ui/classes.ts` 的 `pagePanelClass`、`widePageContainerClass`。
- 暗色主题通过 token 覆盖，不写死浅色背景。

## 8. 改页面前检查

1. 新路由是否补了 `getStaticPaths`，URL 是否带尾斜杠。
2. 列表数据是否走 feed，详情数据是否走 `getAllPosts()`。
3. 新静态页是否同时补了 `data/<pageId>/*.json` 和 `src/entities/page-content/model/<pageId>.ts`。
4. 新增交互是否登记了 `data-*` 属性，是否只在 `src/features/` 或 `src/app/scripts/` 内。
5. 改主题归属只改 `data/vendors/themes.json`；主题页不得引入文章列表。
6. 改完跑 `npm run build` 和 `npm run check:budget`。
